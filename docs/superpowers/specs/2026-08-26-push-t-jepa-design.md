# CPU 优先的 Push-T JEPA 与 CEM 设计

## 目标

在本地构建一个自包含、可复现且可测试的最小实验：使用手写的二维 Push-T 仿真采集图像轨迹，训练动作条件 JEPA 世界模型，并以 CEM 搜索使预测终点 embedding 接近目标图像 embedding 的动作序列。

## 范围与非目标

本项目优先保证 CPU 上的可读性、确定性和端到端闭环。环境是二维俯视近似，不试图严格复刻 Diffusion Policy 的 Push-T 或真实摩擦物理；首版不使用 Gymnasium、Pymunk、Pygame、GPU 或在线强化学习。

## 架构

### 环境

`PushTEnv` 是 64x64 RGB 俯视环境。状态包含圆形推杆的位置、T 形物体的平面位置与旋转角，以及固定的场景边界。动作为归一化二维位移，由环境裁剪至最大步长。

环境使用确定性的轻量规则：推杆与 T 物体接近且动作朝向物体时，T 沿推动方向平移，并按接触点偏离质心的程度产生有界角速度；所有物体都进行边界裁剪。环境提供 `reset`、`step`、`render` 和只读状态访问。渲染不依赖 GUI，使用 Pillow 生成图像数组。

### 数据

数据采集使用带随机探索的简单推杆策略，保存短轨迹。训练样本为 `(当前图像, 动作序列, 未来图像)`：动作序列长度默认 4。数据集必须携带随机种子，并能由内存数据或保存的轨迹构造。

### JEPA 世界模型

上下文编码器将当前图像映射到 64 维 embedding `z_t`。目标编码器具有同构小型 CNN，以 EMA 方式由上下文编码器更新，且不参与反向传播。动作条件预测器接收 `z_t` 与未来 4 步动作，输出预测 embedding `z_hat_tk`。优化目标是 `MSE(z_hat_tk, z_tk)`。

模型不尝试像素重建：规划和评估均在 embedding 空间进行。

### CEM 规划

给定当前图像和目标图像，分别使用上下文编码器和目标编码器取得 embedding。CEM 对长度为 8 的二维动作序列从截断高斯分布采样 128 条候选；世界模型预测每条候选的终点 embedding；代价是到目标 embedding 的平方欧氏距离，外加小的动作幅度正则。每轮选择 16 条精英，重估均值与标准差，共迭代 3 轮。

执行采用滚动时域：只执行最优序列的第一个动作，然后根据真实环境新观察再次规划。演示使用固定目标或可设定种子的随机目标，并导出带轨迹的 GIF 或 PNG。

## 目录与职责

```text
push_t_jepa/
  config.py      # 不可变默认配置、随机种子与路径
  env.py         # 动力学、状态、确定性 Pillow 渲染
  dataset.py     # 轨迹生成、持久化、训练样本
  model.py       # 编码器、预测器、JEPA 封装与 EMA
  train.py       # 训练循环、验证、检查点和指标
  planner.py     # CEM 及滚动规划
  demo.py        # 命令行演示与图像/GIF 导出
tests/
  ...            # 独立模块测试和端到端 smoke test
```

`artifacts/` 存放数据、检查点、训练指标和演示产物，不纳入源码控制。

## 默认 CPU 配置

- 图像：64x64 RGB。
- embedding：64 维。
- 预测步数：4。
- 数据：默认约 5,000 条短轨迹；smoke 配置更小。
- CEM：horizon 8、候选数 128、精英数 16、迭代数 3。
- 依赖：Python、NumPy、PyTorch、Pillow、pytest。
- 设备：默认 CPU；代码可接受显式设备参数，但不依赖 CUDA。

## 可靠性与错误处理

所有运行入口接受随机种子，且环境和 CEM 在同种子下可重复。训练保存配置、指标和检查点。检查点缺失、张量形状不兼容、非法动作范围或无效 CEM 参数必须抛出中文说明的 `ValueError` 或 `FileNotFoundError`。

## 验收与测试

1. 环境渲染输出正确的图像形状；边界裁剪有效；接触推动能改变 T 的位姿。
2. 数据集样本具有正确图像、动作序列和未来图像形状，且同种子采集结果一致。
3. 模型前向输出形状正确，目标编码器无梯度，EMA 更新会改变目标参数。
4. CEM 的候选动作均在合法范围内；在固定、确定性的小场景中，规划终点到目标的真实几何距离优于固定随机动作基线。
5. smoke 训练能完成一个极小 epoch，验证损失为有限值，并能加载检查点规划和输出演示产物。

## 用户工作流

1. 安装依赖。
2. 运行 smoke 测试确认环境、训练和规划闭环。
3. 运行训练命令生成或复用数据，并写入检查点。
4. 运行演示命令，传入模型检查点和固定或随机目标，查看导出的 GIF/PNG 和指标。
