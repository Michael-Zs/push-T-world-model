# Pymunk Push-T 环境迁移设计

## 目标

将当前基于近似接触规则的 `PushTEnv` 替换为由 Pymunk/Chipmunk2D 驱动的二维刚体环境，使推杆接触 T 物体时产生可信的碰撞、摩擦、旋转和边界响应，同时保持 JEPA、CEM、训练及演示的公共接口。

## 范围

- 使用 Pymunk 实现环境动力学。
- 推杆是可控的运动学圆形刚体；T 是由两块矩形 shape 组成的单一动态刚体。
- 四面边界为静态线段 shape。
- 保留 `reset(seed)`、`step(action)`、`render()`、`state` 与 `set_state()` 接口。
- 动作仍是归一化二维控制量，转为每个环境步的推杆目标速度；一个 `step` 内进行固定次数物理子步。
- Pillow 保持离屏 RGB 渲染；不要求 Pygame 窗口。
- 旧的手写规则移除，不与 Pymunk 环境混用。

## 非目标

- 不复刻真实机器人控制器、连续接触求解或真实相机噪声。
- 不保留旧手写环境产生的数据与新物理数据混合训练。

## 动力学模型

世界坐标是 `[0, 1] x [0, 1]`。T 物体采用质量 1、有限转动惯量、摩擦系数 0.8、弹性 0；推杆采用运动学圆形 body，半径 0.045、摩擦 0.7、弹性 0。环境每一步将归一化动作乘最大控制速度，运行 8 个固定 `dt=1/240` 子步。Pymunk 负责接触法线、穿透修正和角速度。

T 的本地形状由横梁和竖杆两个矩形组成，分别附加到同一个 body；渲染时从 Pymunk body 的位置与角度计算顶点。`state` 直接读取 Pymunk 的推杆位置、T body 位置和角度。

## 兼容性与数据

`EnvConfig` 增加物理参数（子步数、时间步长、推杆最大速度、摩擦）。`image_size` 继续独立参数化，可使用 64 或 256；训练命令的 `--image-size` 将传递到环境和模型。

动力学变化使旧轨迹和 checkpoint 不再适合作为正式规划模型。迁移后需要以 Pymunk 环境重新采集数据并重新训练；旧 checkpoint 仅能用于代码兼容检查。

## 测试与验收

1. 同种子 reset 和同一动作序列产生相同状态与渲染。
2. 推杆接触 T 后 T 的位置改变；偏心接触产生非零角度。
3. 推杆和 T 都不穿越静态边界；推杆不会穿透 T。
4. 渲染形状遵循 `EnvConfig.image_size`。
5. 数据集、smoke 训练与 CEM 演示在 64 和 256 两种尺寸下完成。
6. CEM 演示 GIF 中能够观察到 Pymunk 产生的 T 旋转。

## 依赖与使用

在 `pyproject.toml` 添加 `pymunk` 运行时依赖。安装后运行完整 pytest，重新运行训练，再用新 checkpoint 运行演示。
